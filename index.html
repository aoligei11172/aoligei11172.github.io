网络空间测绘引擎对比与子域名收集实践
2026/11/2

声明：本文所有检索均为平台侧公开数据查询，未向任何目标发送探测请求，未进行扫描与爆破，仅用于课程作业。文中 IP 为搜索引擎已收录的公开记录。

一、和 ZoomEye 类似的网站

网站 国家 特点
ZoomEye 中国 指纹多，中文资产多
Shodan 美国 最早，端口/设备最全
Censys 美国 擅长证书检索
FOFA 中国 国内最常用，语法强
360 Quake 中国 中文资产多，可看原始响应
Hunter 鹰图 中国 按单位查资产

二、ZoomEye 搜索演示

2.1 按域名查：domain:"github.com"

项目 数值
命中总数 53,308 条
近一年 31,008 条
耗时 1.228 秒
设备 52,458（IPv4 52,454 / IPv6 4）
网站 850

三点观察：

  1. IPv4 有 5 万多条，IPv6 只有 4 条，说明 IPv6 资产基本没被收录，是观测盲区。
  2. 总数 5.3 万但近一年只有 3.1 万，说明库里存的是历史扫描记录，命中条数 ≠ 资产个数。
  3. 结果里出现了 drafts.misty.moe、162.35.243.250 这类不是 github.com 子域名的记录，说明 domain: 匹配范围比预想宽，会命中页面或证书里引用了该域名的主机。所以它适合看「暴露了什么」，不适合当子域名清单。

2.2 按组件查：app="Open WebUI"

项目 数值
命中总数 93,123 条
近一年 48,197 条
耗时 0.272 秒

样本：196.221.164.57:9898，埃及开罗，标题 Open WebUI，响应头 server: uvicorn。

观察：Open WebUI 默认端口是 3000，这里改成了 9898，但还是被扫到了——改默认端口没用。uvicorn 说明前面没有 Nginx 之类的反向代理，服务是直接暴露的。这类自建 AI 面板近一年增长很快（近一年占一半以上），通常默认口令简单甚至无鉴权。

2.3 按语言查：app="PHP"

项目 数值
命中总数 111,076,437 条
近一年 24,989,076 条
设备 94,521,305
网站 16,555,132
耗时 1.109 秒

样本：license.processmaker.com:443，响应头是

Server: Apache/2.4.61 (Amazon) OpenSSL/1.0.2k-fips PHP/5.4.45

观察：一个 Server 头就把三个组件的精确版本全暴露了。

  • PHP/5.4.45：PHP 5.4 分支 2015 年就停止支持了
  • OpenSSL/1.0.2k：1.0.2 系列 2019 年底维护结束
  • Apache/2.4.61：相对较新

也就是说运维升级过 Apache，但应用层没跟上。反过来看另一条样本只返回 Server: Apache（不带版本号），信息更少，反而更安全。

防守动作：关掉 banner 里的版本号（ServerTokens Prod、expose_php = Off），并盯着组件的停止支持时间。

三、子域名收集

3.1 两类方法

类型 做法 是否碰目标
被动收集 查证书日志、DNS 数据集、测绘引擎已有记录 不碰
主动爆破 用字典向目标 DNS 发大量查询 碰，必须有授权

本次只做被动收集，示例目标用公开域名 github.com。

3.2 拿清单

两种方式都能拿到子域名清单：

  • SecurityTrails：securitytrails.com 搜 github.com，页面下方 A Records 表格的 Host 列就是子域名。
  • 公开 DNS 采集接口：如 HackerTarget 的 hostsearch，直接返回 子域名,IP 的表格。

下面是通过公开 DNS 接口实际查到的部分结果（单次返回前 50 条）：

子域名 IP
accelerator.github.com 185.199.110.153
accessibility.github.com 185.199.111.153
action.github.com 185.199.108.153
api.github.com 140.82.113.5
codeload.github.com 140.82.114.9
classroom.github.com 140.82.114.17
copilot.github.com 140.82.113.18
community.github.com 140.82.114.18
cdn-185-199-108-153.github.com 185.199.108.153
admin.github.com 140.82.114.23

两点观察：

  1. IP 高度集中在两个网段：185.199.x.x（GitHub Pages 静态托管）和 140.82.11x.x（GitHub 主站集群）。看到网段基本就能判断这台主机是「静态页」还是「业务接口」。
  2. 有些子域名把 IP 直接写进了名字，比如 cdn-185-199-108-153.github.com——命名规则本身就是信息泄露，连查都不用查。

3.3 用证书日志补漏

HTTPS 证书里会写清楚签发时的全部域名，所以证书日志能查到页面上看不到的子域名：

https://crt.sh/?q=%25.github.com

很多公司内部系统、测试环境就是从证书日志里被翻出来的，属于典型的「影子资产」。

3.4 三个数据源的区别

数据源 能查到什么 局限
ZoomEye 端口、服务、banner、标题 只收录被扫过的主机，domain: 会串入非子域记录
SecurityTrails / DNS 接口 子域名 + IP，覆盖全 看不到服务暴露情况
crt.sh 隐藏的子域名 通配符证书噪声多

结论：测绘引擎看「跑什么服务」，DNS 数据集看「有哪些子域名」，证书日志补漏，三者要一起用。

3.5 访问验证

从清单里挑几个打开，确认是不是活的站点：

子域名 页面
api.github.com 返回 JSON，说明是接口服务
gist.github.com 代码片段服务
education.github.com 教育服务

访问时只用浏览器打开首页看一眼，不做任何点击以外的操作。

四、总结

  1. 测绘引擎各有侧重，做资产梳理要多平台交叉比对。
  2. 看懂数字口径：总数 和 近一年、设备 和 网站 差别很大，引用时必须写清。
  3. banner 本身就是情报：一个响应头就能看出组件有没有停在旧版本上。
  4. 语法要实测：domain: 会命中非子域记录，不试就照抄容易出错。
  5. 全程只查公开数据，不做主动探测。
