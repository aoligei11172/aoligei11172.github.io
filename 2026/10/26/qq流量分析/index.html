wireshark QQ 流量分析（PC—手机）

2026/10/26 Security

一、实验目的

使用 Wireshark 分析 PC 与手机之间的 QQ 文件传输流量，回答三个问题：使用 UDP 还是 TCP、数据是否加密、能否直接恢复文件。

二、实验过程

实验设备为一台电脑和一部手机，两端登录同一 QQ 号，通过“我的设备”发送测试消息和文件。

在电脑的真实 WLAN 网卡上使用wireshark抓包，保存为 pc-phone.pcapng。打开“统计 → 对话”，按流量大小找到一条约 3 MB 的 TCP 候选会话，其服务器端口为 443，Stream ID 为 133。

使用以下过滤器查看该会话：

tcp.stream eq 133

三、问题分析

1. UDP 还是 TCP

Stream 133 中存在明确的 TCP 数据包和连接信息，因此该候选会话使用 TCP。UDP 对话主要是 DHCP、广播和 mDNS 等小包，没有发现对应的大流量文件会话。

2. 加密还是明文

该会话中的大量数据包显示为：

TLSv1.3    Application Data

说明应用数据由 TLS 1.3 加密，无法直接看到文件明文。

3. 能否恢复文件

明文文件通常可以根据文件头定位，例如 PNG 的 89 50 4E 47、ZIP 的 50 4B 03 04。但本次候选会话的载荷已经加密，即使追踪 TCP 流并保存原始数据，得到的也主要是 TLS 密文，而不是原始文件。

因此，无法仅凭这份抓包直接恢复文件。

四、实验结论

问题 结论
UDP 还是 TCP TCP
加密还是明文 TLS 1.3 加密
能否直接恢复文件 不能从该加密会话中直接恢复

以上结论仅针对本次抓取的重点候选会话，不代表所有 QQ 版本和传输场景。由于尚未通过 QQ 进程 PID 绑定该连接，流量归属还可以通过进程、端口和操作时间进一步验证。
